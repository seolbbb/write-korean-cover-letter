# write-korean-cover-letter

> AI와 함께 자기소개서를 100편 가까이 썼습니다. 문장은 매끈해졌지만 서류 결과는 좋아지지 않았습니다.
>
> 그래서 공개 합격 자기소개서 223건을 다시 읽고, 그중 73건을 같은 기준으로 코딩해 한국어 자기소개서 작성 Skill로 만들었습니다.

**공개 합격 사례 223건 검토 · 대표 답변 73건 동일 기준 코딩 · 문항 유형 8개 · 사실과 수치 우선**

`write-korean-cover-letter`는 한국어 자기소개서를 대신 꾸며 주는 프롬프트 모음이 아닙니다. 문항이 묻는 내용, 지원자가 실제로 한 판단과 행동, 확인 가능한 결과, 목표 직무와의 거리를 먼저 따지는 Codex Skill입니다.

합격을 보장하지 않습니다. 대신 AI가 자소서를 쓸 때 가장 위험한 세 가지, 즉 **질문을 비껴가는 글**, **팀 성과를 개인 성과로 바꾸는 글**, **확인되지 않은 수치를 그럴듯하게 쓰는 글**을 줄이는 데 집중합니다.

## 왜 만들었나

처음에는 AI에게 공고와 경험을 넣고 “더 설득력 있게 써 달라”고 요청했습니다. 답변은 빠르고 자연스러웠습니다. 문제는 자연스러운 문장이 반드시 좋은 자기소개서는 아니라는 점이었습니다.

- 회사 소개가 길고 정작 지원자는 보이지 않았습니다.
- 기술 이름은 많았지만 왜 그 방법을 골랐는지는 빠졌습니다.
- 팀의 결과가 어느 순간 개인의 성과로 바뀌었습니다.
- 서로 다른 기록의 숫자 중 하나를 AI가 임의로 골랐습니다.
- 마지막 문장은 늘 “기여하겠습니다”로 끝났습니다.

물론 제가 떨어진 이유가 전부 자기소개서였다고 말할 수는 없습니다. 다만 같은 방식으로 계속 쓰는 동안에는 무엇이 잘못됐는지조차 알기 어려웠습니다. 그래서 합격 사례의 문장을 흉내 내는 대신, 여러 직무에서 반복되는 구조와 공식 채용 지침이 함께 지지하는 원칙을 찾았습니다.

## 무엇을 분석했나

- 잡코리아와 링커리어의 공개 합격 사례를 URL 기준으로 중복 제거해 **223건**을 검토했습니다.
- 대기업·공공기관 36건과 기술·플랫폼 직무 37건, 총 **73건의 대표 답변**을 같은 기준으로 코딩했습니다.
- 고용24, NCS 공정채용 자료, 공공기관 실제 평가표를 함께 대조했습니다.
- 원문을 대량 복제하지 않고 문항 적합성, 본인 판단, 행동, 결과, 직무 전이 같은 구조만 기록했습니다.

분석에서 의외였던 점도 있습니다. 숫자, 소제목, 완전한 STAR 구조는 합격 사례의 절반 안팎에서만 나타났습니다. 반면 본인이 실제로 한 행동, 결과나 학습, 직무에서 다시 쓸 수 있는 방식은 훨씬 자주 확인됐습니다.

표본 구성, 코딩 기준, 근거 등급과 한계는 [방법론 문서](docs/METHODOLOGY.md)에 정리했습니다.

## 이 Skill이 하는 일

### 1. 공고를 일반론보다 먼저 봅니다

현재 문항, 하위 질문, 글자 수, 제출 형식, 블라인드 지침을 가장 높은 규칙으로 둡니다. STAR나 두괄식 같은 일반론이 공고와 충돌하면 공고를 따릅니다.

### 2. 사실 장부를 만듭니다

본인의 행동, 타인의 행동, 팀 결과, 수치의 기준과 범위를 분리합니다. 기록이 충돌하면 하나를 골라 쓰지 않습니다. 확인 전에는 빼거나 공통으로 성립하는 표현으로 낮춥니다.

### 3. 직무와 가장 가까운 경험을 고릅니다

경험의 화려함보다 다음 네 가지를 비교합니다.

- 해결한 문제
- 사용한 정보와 도구
- 협업한 이해관계자
- 결과를 판단한 기준

### 4. Q–E–J–A–R–T로 빠진 근거를 찾습니다

`질문에 대한 답 → 필요한 맥락 → 판단 → 행동 → 결과 → 직무 전이`를 확인합니다. 고정 문장 템플릿이 아니라 누락 점검표로만 사용합니다.

### 5. 문항에 맞는 구조를 선택합니다

지원동기, 직무역량, 문제해결, 협업·갈등, 실패·약점, 성장·가치관, 입사 후 계획, 산업 이슈의 8개 유형을 지원합니다. 그대로 복사할 완성 문장 대신 평가 의도와 필요한 증거 흐름을 제공합니다.

### 6. 문체는 마지막에 고칩니다

사실과 구조가 확정된 뒤에만 번역투, 명사 나열, 반복되는 종결, 과도한 소제목을 다듬습니다. 문체를 자연스럽게 만든다는 이유로 새로운 성과나 교훈을 추가하지 않습니다.

## 설치

Codex에서 `$skill-installer`를 사용할 수 있다면 아래처럼 요청하는 방법이 가장 간단합니다.

```text
$skill-installer를 사용해서 seolbbb/write-korean-cover-letter 저장소의
write-korean-cover-letter Skill을 설치해줘.
```

직접 설치하려면 저장소의 `write-korean-cover-letter/` 폴더를 다음 위치로 복사합니다.

```text
$CODEX_HOME/skills/write-korean-cover-letter
```

`CODEX_HOME`을 따로 설정하지 않았다면 기본 위치는 `~/.codex/skills/write-korean-cover-letter`입니다. 설치가 끝나면 새 대화에서 사용할 수 있습니다.

## 사용 예시

### 새 답변 작성

```text
Use $write-korean-cover-letter to draft answers for this Korean job posting.
Read the posting and my experience notes first. Do not invent facts.
Explain why you selected each experience, then separate the submission text
from facts that still need confirmation.
```

### 기존 자기소개서 검토

```text
$write-korean-cover-letter로 이 자기소개서를 검토해줘.
문항 적합성, 본인 기여, 수치 범위, 문항 간 경험 중복부터 확인하고
내용 검증이 끝난 뒤에만 문체를 다듬어줘.
```

### 사실과 수치만 감사

```text
$write-korean-cover-letter를 사용해 제출본의 사실 장부를 만들어줘.
내 행동, 팀 결과, 타인의 판단, 충돌하는 수치와 면접에서 확인할 항목을
분리하고 아직 확인되지 않은 문장은 다시 쓰지 마.
```

## 검증

Skill 형식 검증과 참조 링크 검사를 통과했습니다. 실제 지원서 자료를 사용한 회귀검증은 서로 다른 세 직무군에서 진행했습니다.

- AI·LLMOps 제품 기획
- 반도체 Product Engineering
- 제조 현장 기술엔지니어

검증 과정에서 `배치당 30초`를 `전체 처리 30초`로 바꾸는 수치 범위 오류와, 팀이 도출한 결과를 지원자가 직접 전달한 것처럼 쓰는 주체 오류를 발견했습니다. 두 문제를 하드게이트로 추가한 뒤 다시 테스트했습니다. 개인 지원서와 경험 원문은 저장소에 포함하지 않습니다.

## 한계와 원칙

- 공개 합격 사례에는 탈락 비교군이 없어 특정 표현의 합격 효과를 증명할 수 없습니다.
- “합격”이 서류, 인턴, 최종 합격 중 어느 단계인지 불명확한 사례가 있습니다.
- 현재 지원 공고와 평가 기준이 이 저장소의 모든 일반 원칙보다 우선합니다.
- 이 Skill은 합격을 보장하지 않으며, 사용자는 제출 전 사실과 글자 수를 직접 확인해야 합니다.
