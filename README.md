# write-korean-cover-letter

> **AI와 함께 쓰는 자기소개서, 고쳐도 고쳐도 끝이 없나요?**
>
> 무한 수정에 지쳐서 만들었습니다. 환각, AI 특유의 말투, 문항과 맞지 않는 경험, 직무기술서를 옮겨 적은 듯한 지원동기, 읽는 사람보다 키워드만 앞세운 글, 여러 답변에 반복되는 같은 이야기부터 잡습니다.

이 Skill을 설치한 다음 **자기소개서에 쓸 경험, 이전 지원서, 포트폴리오를 정리해 둔 폴더에서 에이전트를 실행하세요.** 공고와 문항을 건네면 폴더의 자료부터 읽고, 어떤 경험을 어느 문항에 쓸지 정한 뒤 초안을 작성합니다.

**분석 근거:** 잡코리아·링커리어에서 합격 사례로 공개된 자기소개서 223건을 AI와 함께 구조 중심으로 살폈습니다. 이 가운데 73개 답변은 질문에 제대로 답했는지, 지원자가 어떤 판단을 내리고 무엇을 했는지, 결과와 직무 연결이 있는지를 같은 항목으로 비교했습니다. 고용24·NCS 공정채용 자료·공공기관 평가표도 함께 확인했습니다.

## 바로 시작하기

### Claude Code · Codex CLI — 클론 + 스크립트

```bash
git clone https://github.com/seolbbb/write-korean-cover-letter.git
cd write-korean-cover-letter
./install.sh
```

- 설치된 `claude`와 `codex`를 자동 감지해 전역 Skill 경로에 심링크합니다.
- Claude Code: `/write-korean-cover-letter` · Codex: `$write-korean-cover-letter`
- 한쪽만 설치: `./install.sh --claude-only` 또는 `./install.sh --codex-only`
- 제거: `./uninstall.sh`
- 업데이트: `./update.sh` — 새 버전을 확인해 `git pull` 후 재설치합니다. `./update.sh --check`은 업데이트 유무만 확인합니다.

Windows에서는 WSL 또는 개발자 모드가 켜진 Git Bash에서 실행하세요. 심링크 권한이 없으면 스크립트가 설치를 중단합니다.

## 이 Skill이 하는 일

### 1. 폴더의 경험 자료부터 읽습니다

사용자가 매번 경력과 프로젝트를 다시 붙여 넣지 않아도 됩니다. 경험 메모, 이전 지원서, 포트폴리오, 프로젝트 기록을 읽고 사용할 수 있는 사실과 아직 확인되지 않은 내용을 나눕니다.

### 2. 공고와 문항의 제출 조건을 먼저 잠급니다

현재 문항, 하위 질문, 글자 수, 제출 형식, 블라인드 지침을 확인합니다. 사용자의 수정 범위와 이미 합의한 내용을 보존하며, STAR나 두괄식 같은 일반론을 모든 문항에 강요하지 않습니다.

### 3. 문항마다 가장 가까운 경험을 고릅니다

질문에 무엇으로 답할지 정하고 그 답에 필요한 경험을 고릅니다. 직무역량은 실제 과업과 가까운 판단·행동을, 약점과 가치관은 반복된 실천과 변화를 봅니다. 경험 수를 고정하지 않고, 짧은 업적 나열이 되면 핵심 사례를 깊게 설명합니다. 여러 문항의 소재와 역할도 함께 배분합니다.

### 4. 환각을 막는 사실 장부를 만듭니다

본인의 행동, 타인의 행동, 팀 결과, 수치의 기준과 범위를 분리합니다. 기록이 충돌하면 하나를 골라 쓰지 않습니다. 확인 전에는 빼거나 공통으로 성립하는 표현으로 낮춥니다.

### 5. 질문 유형에 따라 필요한 근거를 바꿉니다

지원동기, 직무역량, 문제해결, 협업·갈등, 실패·약점, 성장·가치관, 입사 후 계획, 산업 이슈의 8개 유형을 구분합니다. 질문마다 평가자가 확인하려는 내용과 필요한 증거가 다르므로 같은 STAR 틀을 모든 답변에 강요하지 않습니다.

### 6. 직무기술서를 복사하지 않고 경험과 연결합니다

해야 하는 일과 그 일을 수행하는 데 필요한 능력을 구분합니다. 예를 들어 기능 실행은 과업이고, 모델과 API의 입출력·상태를 연결하는 시스템 설계는 필요한 능력입니다. 실제 판단과 구현 과정으로 이를 보여줍니다. 지원동기는 관심이 생긴 실제 배경과 회사·직무를 선택한 이유를 쓰고, 요구하지 않은 프로젝트 소개나 입사 후 다짐으로 채우지 않습니다.

### 7. 읽는 사람을 고려해 문장을 정리합니다

`질문에 대한 답 → 필요한 맥락 → 판단 → 행동 → 결과 → 직무 전이`를 확인합니다. 고정 문장 템플릿이 아니라 누락 점검표로만 사용합니다.

프로젝트 이름만으로 설명을 시작하지 않고, 만든 것과 문제를 이해할 최소 배경을 줍니다. 원인과 결과가 성립하는지, 예시가 전체 목표를 보여주는지, 병렬인 기능을 억지 순서로 묶지 않았는지 확인한 뒤 문체를 다듬습니다. 접속사 자체를 금지하지 않으며 자연스럽게 보이려고 새로운 성과나 교훈을 만들지 않습니다.

부분 수정에서는 합의한 문단과 제외한 소재를 보존합니다. 문장 하나를 고쳐도 앞뒤 문장과 문단 전체를 다시 확인합니다.

### 8. 제출 전 전체 답변을 함께 검사합니다

최신 실제 제출본에서 문항 적합성, 논리, 기여·수치의 범위, 문항 간 중복, 문법·오타·글자 수를 함께 확인합니다. 발견 사항은 **제출 전 수정 필요 / 선택적인 개선 / 현재 글의 한계**로 나눠 모아서 제시합니다. 새 오류는 정정하되, 취향에 따른 수정을 계속 필수로 바꾸며 제출을 미루지 않습니다.

## 사용 예시

### 새 답변 작성

```text
이 폴더의 경험 자료와 이전 지원서를 먼저 읽어줘.
아래 공고의 문항별 요구사항을 나누고 각 문항에 쓸 경험이 겹치지 않게 배분해줘.
선정 이유를 설명한 다음 초안을 작성하고 확인이 필요한 사실은 제출문과 분리해줘.
```

### 기존 자기소개서 검토

```text
$write-korean-cover-letter로 이 자기소개서를 검토해줘.
문항 적합성, 본인 기여, 수치 범위, 문항 간 경험 중복부터 확인하고
내용 검증이 끝난 뒤에만 문체를 다듬어줘.
```

### 합의한 내용을 보존하며 부분 수정

```text
1문단의 소재와 메시지는 유지하고 2문단의 연결만 다듬어줘.
새로운 경험이나 성과는 추가하지 말고, 수정 뒤 앞뒤 문단과의 논리도 확인해줘.
```

### 최종 제출 판단

```text
첨부한 최신 파일을 실제로 읽고 전체 문항을 함께 검토해줘.
제출 전 꼭 고칠 문제를 한 번에 모아 주고, 선택적인 개선과 글의 한계는 구분해줘.
공백과 줄바꿈을 어떻게 계산했는지도 알려줘.
```

### 사실과 수치만 감사

```text
$write-korean-cover-letter를 사용해 제출본의 사실 장부를 만들어줘.
내 행동, 팀 결과, 타인의 판단, 충돌하는 수치와 면접에서 확인할 항목을
분리하고 아직 확인되지 않은 문장은 다시 쓰지 마.
```

## 한계와 원칙

- 공개 합격 사례에는 탈락 비교군이 없어 특정 표현의 합격 효과를 증명할 수 없습니다.
