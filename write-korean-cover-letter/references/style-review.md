# 한국어 문체 검토

내용·사실·수치가 확정된 뒤에만 적용한다. 이 문서는 `humanize-korean`의 범용 원칙 중 자기소개서에 필요한 부분만 추린 보수적 검토 기준이다. 사용자가 해당 Skill을 명시하면 이 문서로 대체하지 말고 설치된 `humanize-korean`을 직접 읽고 따른다.

## 1. 의미를 잠근다

- 고유명사, 수치, 날짜, 결과, 인용, 기술 용어를 임의로 바꾸지 않는다.
- 문체를 고치면서 새로운 판단·성과·동기·교훈을 추가하지 않는다.
- 격식체를 유지하되 불필요하게 문어적인 `하였습니다`로 올리지 않는다.

## 2. 도입을 검사한다

첫 문장이 질문에 답하는지 확인한다. 다음 표현은 금지어가 아니라 점검 신호다.

- 입사를 준비하며
- 공고를 살펴보며
- 해당 직무는 ~라고 이해했습니다
- 제가 회사를 선택할 때

실제 시간 흐름이나 판단에 필요하지 않다면 삭제하고 답부터 쓴다.

## 3. 번역투와 명사 나열을 줄인다

- `~에 대해`, `~를 통해`, `~에 있어서`, `~에 기반하여`가 반복되면 직접 목적어와 동사로 바꾼다.
- `분석 및 전처리, 선정 및 학습을 진행했습니다`처럼 명사를 늘어놓지 않는다.
- `진행했습니다`, `수행했습니다`, `활용했습니다`만 반복하지 말고 실제 행동 동사를 쓴다.
- 이중 피동과 `가지고 있습니다`식 직역을 줄인다.

## 4. 문장 호흡을 조정한다

- 문장마다 주장, 맥락, 판단, 행동, 결과, 직무 전이 중 하나의 중심 기능을 둔다.
- 배경·행동·결과·포부를 한 문장에 모두 넣지 않는다.
- 비슷한 길이와 구조의 문장만 이어지지 않게 한다.
- 관련된 원인과 대비는 한 문장으로 묶되, 한 문장에 상황·행동·결과를 모두 넣어 과도하게 늘이지 않는다.
- 한 문장짜리 문단이 연속되면 의미 단위로 합친다.
- `했습니다`가 네 문장 이상 연속되면 문장 구조와 종결을 조정한다.
- 연결어미 뒤 쉼표와 문두 `또한`, `따라서`, `즉`의 반복을 점검한다.

문장 길이 수치는 합격 기준이 아니다. 문항·글자 수·독자의 이해에 맞춰 짧은 주장 문장과 충분한 근거 문장을 섞는다.

## 5. 소제목을 선택적으로 사용한다

- 공고가 소제목을 요구하면 지정 형식을 따른다.
- 글자 수에 여유가 있고 `역량+결과` 또는 `문제+전환`을 본문보다 빠르게 보여 줄 때만 사용한다.
- 명언·해시태그·감성적 비유·자기평가를 장식처럼 붙이지 않는다.
- 소제목을 쓰지 않아도 첫 문장에서 답이 보이면 억지로 추가하지 않는다.
- 소제목 사용 여부를 합격 규칙으로 취급하지 않는다.

## 6. AI식 연결과 결론을 점검한다

다음 표현은 구체적인 근거를 대신할 때만 고친다.

- 바로 연결됩니다
- 맞닿아 있습니다
- 이를 통해 성장했습니다
- 실질적인 가치를 창출하겠습니다
- 담당자에게 필요한 솔루션을 제공하겠습니다
- 일부 단계만 보지 않고 전체를 보았습니다

문장 자체를 자동 삭제하지 않는다. 앞 문장이 이미 보여 준 행동·판단·결과로 바꾸거나, 필요한 경우 그대로 둔다.

## 7. 기술 용어를 보존한다

- 공고가 요구하는 도구, 실제 역량을 증명하는 프로그램, 업계 표준 용어는 보존한다.
- 기술명을 한국어로 억지 번역하지 않는다.
- 비전문 독자에게 낯선 기술은 첫 등장에 기능을 짧게 설명한다.
- 정확한 제품명이나 모델 크기가 판단에 불필요할 때만 일반 기능명으로 낮춘다.

## 8. 최종 점검

- 질문의 답이 첫 문단에 있는가
- 문장마다 중심 기능이 하나로 보이는가
- 주체와 사실이 달라지지 않았는가
- 수치와 적용 범위가 보존됐는가
- 회사·직무 용어가 경험을 대신하지 않는가
- 기술 이름이 너무 많거나 지나치게 삭제되지 않았는가
- 문장 길이와 종결이 단조롭지 않은가
- 접속사와 메타 문장이 반복되지 않는가
- 글자 수 제한에 여유가 있는가

한두 표현을 기계적으로 바꾸기보다 전체 문단의 흐름을 확인한다. 자연스러운 원문을 규칙에 맞추려고 과도하게 고치지 않는다.
